# tcp-server-client

一个用于学习 Linux TCP 网络编程、事件驱动模型和线程池的 C++20 Echo 客户端/服务端项目。

服务端监听 `127.0.0.1:8888`，通过 `epoll` 事件循环分发事件，使用线程池处理已建立连接的文本回显。项目包含交互式客户端、TCP 功能测试和多线程并发测试程序。

## 特点

- 使用 C++20 和现代 CMake 组织目标，无第三方库依赖
- 封装 `Socket`、`InetAddress` 和 `Buffer` 等基础组件
- 通过 `Epoll`、`Channel` 和 `EventLoop` 实现事件分发
- 已建立连接的 socket 使用非阻塞 I/O 与边缘触发模式（`EPOLLET`）
- 使用回调连接 `Acceptor`、`Server` 和 `Connection`
- `ThreadPool` 使用任务队列、互斥锁和条件变量，支持提交任务并返回 `std::future`
- 提供 TCP 功能测试，以及每线程独立连接的并发回显测试

> 本项目依赖 `epoll` 等 Linux API，仅适用于 Linux 或 WSL。

## 项目结构

```text
.

├── src/              # 网络库及服务端组件实现

```

## 运行模型

- `EventLoop` 在主线程中等待 `epoll` 事件，由 `Channel` 分发回调。
- `Acceptor` 接受连接，`Server` 管理连接，`Connection` 负责读取与回显。
- `Acceptor` 使用阻塞监听 socket 和水平触发（LT），在事件循环线程中接受连接。
- `EventLoop` 持有默认 **10 个工作线程**的线程池，已建立连接的读取回调提交到线程池。
- 服务端线程池大小由代码决定；并发测试的 `-t` 仅控制测试客户端线程数。

## 构建

环境要求：

- CMake 3.20 或更高版本
- 支持 C++20 的编译器

在项目根目录配置并构建：

```bash
cmake -S . -B build
cmake --build build
```

构建完成后会生成以下可执行文件：

| 文件 | 用途 |
| --- | --- |
| `build/server` | Echo 服务端 |
| `build/client` | 交互式客户端 |
| `build/tcp_test` | TCP 功能测试 |
| `build/test` | 多线程并发测试，对应 `tests/simple_test.cpp` |
| `build/ThreadPoolTest` | 线程池任务提交演示 |

## 使用

在第一个终端启动服务端：

```bash
./build/server
```

在第二个终端启动客户端：

```bash
./build/client
```

客户端从终端读取一行文本并发送。服务端和客户端均可使用 `Ctrl+C` 结束；测试方式见下文。

## 测试

TCP 功能测试和并发测试均需先在另一个终端启动 `./build/server`，无需启动交互式客户端。以下命令均在项目根目录执行。

### TCP 功能测试

功能测试覆盖以下场景：

- 建立连接并回显消息
- 在同一连接中连续收发
- 三个客户端交替收发
- 客户端断开后重新连接

```bash
./build/tcp_test
```

每次发送 1024 字节并逐字节比较回显，收发超时为 2 秒。程序输出各项结果及汇总，退出码 `0` 表示全部通过，`1` 表示存在失败。

当前 `Buffer::append` 遇到 `\0` 会停止追加，因此服务端的文本处理方式与该测试的补零报文不兼容，可能出现接收超时或校验失败。

### 多线程并发测试

`tests/simple_test.cpp` 的负载与收发逻辑对齐 `30dayMakeCppServer/code/day11/test.cpp`，目标端口使用本项目的 `8888`。先创建包含 `-t` 个工作线程的线程池，再提交 `-t` 个客户端任务；每个任务建立一个独立连接，在同一连接上重复收发。

```bash
# 小规模验证：4 个线程，每线程回显 2 次
./build/test -t 4 -m 2

# 请求 10000 个线程，每线程回显 10 次
./build/test -t 10000 -m 10

# 每条连接建立成功后等待 100 秒，再开始回显测试
./build/test -t 10000 -m 10 -w 100

# 查看参数帮助
./build/test --help
```

在 `build` 目录中可直接使用 `./test -t 10000 -m 10 -w 100`。

| 参数 | 含义 | 要求 / 默认值 |
| --- | --- | --- |
| `-t` | 客户端线程池大小，同时也是客户端任务数 | 正整数，默认 `100` |
| `-m` | 每条连接的回显次数 | 正整数，默认 `100` |
| `-w` | 连接成功后、首次发送前的等待秒数 | 可选，非负整数，默认 `0` |

`-w` 对每条连接独立计时，不是等所有连接建立完成后统一开始。它可用于观察连接保持情况；未指定时，连接成功后立即发送。

- 每轮固定发送 `I'm client!`（11 字节），只调用一次 `write`；循环 `read`，累计接收字节数达到发送长度后计数，开始下一轮。
- 每次回显打印 `count: N, message from server: ...`，计数在每条连接内从 `0` 开始；不比较回显内容。
- 不设置连接或收发超时，也不提供完整的短写、`EINTR` 或读取错误处理，与 day11 的简化逻辑一致。
- 不再统计连接峰值、成功率或总耗时；线程池析构时等待客户端任务结束。
- 保留本项目的参数校验和 `--help`；使用自动对象释放客户端资源，调用 `Socket::connect` 时会打印连接日志。

退出码 `0` 不能作为全部回显正确的证明：与 day11 一样，读到 EOF 会直接以 `0` 退出整个进程，写入报错后结束任务也不累计失败。Socket 创建或连接抛出的异常会打印后以 `1` 退出；参数错误返回 `2`。

大规模测试受客户端线程数、内存、文件描述符、终端输出及本机资源竞争影响；`-t 10000` 不代表服务端已经同时接受 10000 个连接。此程序用于复现 day11 的测试方式，不提供严格的性能或正确性结论。

### 线程池演示

无需启动服务端：

```bash
./build/ThreadPoolTest
```

提交两个打印任务，并在销毁线程池时等待任务完成。它是使用演示，没有自动断言；多线程输出顺序和字符交错不固定。

当前 CMake 未注册 CTest 测试，请直接运行上述可执行文件。在测试命令执行后可查看退出码：

```bash
echo $?
```

若提示 `Connection refused`，请确认服务端已启动且正在监听 `127.0.0.1:8888`。`tcp_test` 接收超时表示未在限定时间内取得所需数据；并发测试 `test` 没有收发超时，阻塞时需结合服务端输出排查。

## 当前限制

- IP 地址和端口目前固定为 `127.0.0.1:8888`
- 项目暂未定义独立的应用层消息边界协议；测试中的 1024 字节是测试约定
- 当前按文本处理缓冲区，不支持任意含 `\0` 的二进制数据；发送缓冲区的边界处理仍需完善
- 连接生命周期、共享状态的并发访问，以及非阻塞发送未完成时的处理仍需完善
- 交互式客户端的部分收发和空输入处理仍需完善，测试程序不覆盖终端交互
- 并发测试用于学习和定位问题，不代表服务端已经通过大规模并发能力验证
